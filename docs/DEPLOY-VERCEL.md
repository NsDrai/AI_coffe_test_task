# Деплой на Vercel (база — Neon Postgres)

Инструкция рассчитана на то, что код уже лежит в GitHub-репозитории и вы
работаете в браузере. Ничего ставить локально не нужно, кроме Node.js —
он пригодится на одном шаге (накатить схему базы).

## Что получится

- Сайт живёт на `https://<проект>.vercel.app`;
- каждый `git push` в `main` автоматически деплоит новую версию;
- заявки пишутся в облачный Postgres (Neon);
- `NEXT_PUBLIC_SITE_URL` указывает на продовый адрес;
- бот/менеджер ходят в `/api/leads` по токену.

## Что понадобится

- аккаунт [GitHub](https://github.com) с этим репозиторием;
- аккаунт [Vercel](https://vercel.com) (можно войти через GitHub);
- ничего больше: база создаётся прямо из панели Vercel.

> **Важно про тариф.** План Vercel **Hobby бесплатный, но только для личных
> некоммерческих проектов.** Лендинг мастерской со сбором заявок — это
> коммерческое использование, формально нужен план **Pro**. Решите это до
> публикации, чтобы потом не переносить проект.

## Шаг 1. Код в GitHub

Убедитесь, что последняя версия (с PostgreSQL) запушена:

```bash
git status          # должно быть «working tree clean»
git push origin main
```

`.env.local` в репозиторий не попадает — он в `.gitignore`. Секреты задаются
в панели Vercel (шаг 4).

## Шаг 2. Импорт проекта в Vercel

1. Откройте [vercel.com/new](https://vercel.com/new).
2. **Import Git Repository** → выберите `NsDrai/AI_coffe_test_task`.
3. Framework Preset определится сам как **Next.js**. Root Directory менять не надо.
4. Build Command и Output Directory оставьте по умолчанию (`npm run build`, `.next`).
5. Пока **не** нажимайте Deploy — сначала база и переменные (шаги 3–4).

## Шаг 3. База данных Neon

1. В панели Vercel откройте проект → вкладка **Storage**.
2. **Create Database** → выберите **Neon** (Postgres).
3. Тариф — **Free**, регион — ближайший к вашим пользователям
   (для Минска — **Frankfurt / eu-central-1**).
4. Создайте базу и **подключите её к проекту** (Connect Project).
   Vercel сам подставит переменные окружения: `DATABASE_URL`, `PGHOST`,
   `PGUSER`, `PGPASSWORD`, `PGDATABASE` и другие.

Приложение читает `DATABASE_URL` (или `POSTGRES_URL`), поэтому дополнительно
ничего настраивать не нужно. Убедитесь только, что в `DATABASE_URL` указан
**pooled**-хост (содержит `-pooler`) — он рассчитан на serverless-нагрузку.

**Регион функций.** По умолчанию Vercel выполняет функции в Вашингтоне, а база
будет во Франкфурте — это лишние ~100 мс на каждый запрос. Смените:
Project → **Settings → Functions → Function Region → Frankfurt (fra1)**.

## Шаг 4. Переменные окружения

Project → **Settings → Environment Variables**. Добавьте (окружение —
Production и Preview):

| Переменная | Значение | Обязательна |
| --- | --- | --- |
| `ADMIN_API_TOKEN` | длинный случайный токен | да, иначе `/api/leads` отвечает `503` |
| `NEXT_PUBLIC_SITE_URL` | `https://<проект>.vercel.app` или свой домен | да, иначе в метаданных будет `localhost` |
| `TELEGRAM_BOT_TOKEN` | токен бота от `@BotFather` | если нужны уведомления в Telegram |
| `TELEGRAM_CHAT_ID` | ID чата для уведомлений | если нужны уведомления в Telegram |
| `TELEGRAM_MESSAGE_THREAD_ID` | номер темы в супергруппе | нет |
| `BOT_WEBHOOK_URL` | URL отдельного проекта бота | если уведомления идут в бот |
| `BOT_WEBHOOK_SECRET` | секрет вебхука | нет |
| `POSTGRES_POOL_SIZE` | `2` | нет, но для serverless полезно |

Токен сгенерируйте так:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

`DATABASE_URL` и `PG*` добавлять не нужно — их подставила интеграция Neon.

> `NEXT_PUBLIC_SITE_URL` вшивается в статические страницы **на этапе сборки**.
> Если поменяли значение — нужен редеплой (шаг 7), без него ничего не изменится.

## Шаг 5. Деплой

Вернитесь на вкладку проекта (или нажмите **Deploy**) и запустите деплой.
Через 1–2 минуты получите адрес вида `https://kvarta-landing-xxxx.vercel.app`.

Первый деплой может пройти **до** подключения базы — сайт откроется, но форма
будет отдавать ошибку записи. Это нормально, если вы делали шаги в другом
порядке: после появления переменных достаточно сделать **Redeploy**.

## Шаг 6. Схема базы

Есть два пути.

**Путь A (ничего не делать).** Приложение само создаёт таблицу и индексы при
первой заявке (`DB_AUTO_MIGRATE` по умолчанию включён). Достаточно отправить
тестовую заявку через форму и проверить базу.

**Путь B (надёжнее).** Накатить схему заранее, локально:

```bash
# строка подключения из Neon: Vercel → Storage → ваша база → Connection string
# Windows PowerShell:
$env:DATABASE_URL="postgresql://...-pooler...neon.tech/kvarta?sslmode=require"
npm run db:init
```

Ожидаемый вывод — «Готово: база готова принимать заявки». Ту же команду
используйте, если база уже создана и нужно поставить `DB_AUTO_MIGRATE=false`.

## Шаг 7. Проверка

1. **Здоровье:** откройте `https://<ваш-домен>/api/health` → должно быть
   `{"ok":true,"database":"up",...}`. Если `ok:false` — проблема с базой
   (см. «Если что-то не работает»).
2. **Форма:** отправьте заявку на сайте. Должно появиться всплывающее
   уведомление «Заявка у нас!».
3. **Данные:** Vercel → Storage → база Neon → **Database** → таблица `leads` —
   новая строка на месте.
4. **Источник заявки:** откройте сайт с метками, например
   `https://<домен>/?utm_source=yandex&utm_medium=cpc&utm_campaign=okt`
   и отправьте заявку — в строке заполнятся `utm_*`.
5. **API для бота:**

```bash
curl -s "https://<домен>/api/leads?limit=5" \
  -H "Authorization: Bearer <ADMIN_API_TOKEN>"
```

6. **Смена статуса:**

```bash
curl -X PATCH "https://<домен>/api/leads/1" \
  -H "Authorization: Bearer <ADMIN_API_TOKEN>" \
  -H "content-type: application/json" \
  -d '{"status":"in_progress","by":"@manager"}'
```

## Обновления

Дальше всё просто: `git push origin main` → Vercel собирает и деплоит сам.
Прежние версии остаются в **Deployments**, любую можно вернуть кнопкой
**Promote to Production**.

## Свой домен

Project → **Settings → Domains** → добавьте домен и пропишите DNS-записи,
которые покажет Vercel. После привязки поменяйте `NEXT_PUBLIC_SITE_URL` на
`https://ваш-домен` и сделайте **Redeploy** (см. примечание в шаге 4).

## Если что-то не работает

| Симптом | Причина и решение |
| --- | --- |
| `/api/health` → `ok:false` | Не подключена база или нет переменных. Проверьте, что ресурс Neon подключён к проекту, и сделайте Redeploy — **новые переменные не попадают в уже существующие деплои** |
| Ошибка «Не получилось сохранить заявку» | То же + возможно, не накатана схема. Выполните `npm run db:init` (шаг 6) |
| `/api/leads` отвечает `503` | Не задан `ADMIN_API_TOKEN` в переменных проекта |
| `too many connections` | Используйте **pooled**-строку Neon, понизьте `POSTGRES_POOL_SIZE` до `1–2` |
| В метаданных/OG адрес `localhost` | Не задан или задан неверно `NEXT_PUBLIC_SITE_URL`; нужен Redeploy |
| Первый запрос после паузы идёт 1–3 с | Бесплатный Neon «засыпает» при простое, первый запрос его будит. Для лендинга это нормально |
| Форма молчит, в логах ничего | Project → **Logs** → Functions: ищите строки `[lead]` и `[notify]` |

Логи функций: Project → **Logs**. Там же видны ошибки подключения к базе.

- [ ] Заменены заглушки контактов в `src/lib/site.ts` (телефон, e-mail, Telegram, соцсети)
- [ ] `NEXT_PUBLIC_SITE_URL` указывает на реальный домен
- [ ] Задан `ADMIN_API_TOKEN` (и он не совпадает с примером из `.env.example`)
- [ ] Настроены уведомления (`TELEGRAM_*` или `BOT_WEBHOOK_URL`), проверены тестовой заявкой
- [ ] Функции переведены в регион рядом с базой (Frankfurt)
- [ ] Проверена отправка заявки на проде и её появление в таблице `leads`
- [ ] Решён вопрос с тарифом Vercel (Hobby — только для некоммерческих проектов)
